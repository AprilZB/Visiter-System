脉通多方协同智能化访客系统需求方案说明书
基于钉钉生态与身份证OCR的轻量化免登设计方案
拟制单位：浙江脉通智造科技有限公司文档版本：V2.0.0发布日期：2026年07月

1. 项目概述
1.1 业务背景
当前，浙江脉通智造科技有限公司（以下简称“我司”）由物业保安团队进行统一安全管理。现阶段，园区的来访人员管理仍处于纯传统手工纸质登记的低效状态。当前模式暴露出以下四个核心痛点：
1. 身份核验流于形式：纸质人工填报不仅容易出现错填、漏填或字迹潦草无法辨认的情况，而且保安无法实时核验访客身份的真实性。
2. 协同效率低下：内部员工无法预知谁将到访，外部访客到达后需门岗电话临时确认，多方信息严重断层，极大地浪费了沟通时间成本。
3. 商业秘密保护薄弱：作为一家医疗器械制造企业，外来人员进入厂区或车间涉及核心工艺与商业机密。传统纸质手工登记无法强制要求来访人员签署具备法律效力的保密协议，一旦发生泄密，企业将面临极高的举证与维权成本。
4. 数据资产无法沉淀与安全隐患：敏感的身份信息直接暴露在纸质登记簿上，极易产生隐私泄露风险，且事后难以留痕审计与数字化溯源。
1.2 项目目标
本项目的根本目标是建设一套打通“我司内部员工”、“园区物业保安”与“外部来访人员”三方协同的智能化、轻量化免登访客系统。通过全线上化流程处理，将原有的被动防御转变为主动预控。
2. 角色定义与总体设计原则
2.1 系统用户角色定义
本系统深度融合多方应用场景，主要涵盖外部访客 (Visitor)、内部员工 (Host)、物业保安 (Security) 以及系统管理员 (Admin) 四类角色。
2.2 总体设计原则
【免登轻量化原则】除管理端外，访客端、保安端全部采用基于 Token 鉴权的免登录 H5 交互页面，内部员工依托钉钉原生环境免登，大幅降低系统推广摩擦阻力。【架构数据一致性原则】建立与本地现有基础数据库的单向自动同步机制，确保系统内的人员、部门、汇报上级及主管数据维持绝对最新的企业级一致性。【合规留痕原则】所有外部来访人员必须在线签署保密协议方可生成通行凭证，系统强制将访客OCR身份数据、签署时间、IP及协议版本进行强绑定，形成具备追溯效力的安全审计证据链。

3.3 场景 B：外部访客盲来（现场临时申请流程）
在无任何提前预约的情况下，外部来访人员到达园区正门后的应急流转流程。内部员工或主管在钉钉内点击【同意】后，访客端手机页面自动解锁并强制弹出【保密协议】文本，访客勾选签署后方可获取通行码。
4. 关键技术方案与系统底座对接
4.1 在线保密协议签署技术实现方案
为确保在线保密协议签署具备高度的技术内控与合规审计能力，系统按以下方案设计：
1. 强流程阻断逻辑：采用强流程拦截机制。在外部访客端（H5）流程中，保密协议签署页面位于“审批通过”与“生成通行二维码”之间。访客如果不点击勾选确认，系统后端接口将拒绝下发加密通行Token，从技术层面杜绝未签协议入园的情况。
2. 数字留痕与证据链：数据库新建访客保密协议签署记录表，在访客点击确认时，系统自动抓取并强绑定以下哈希链条：访客OCR真实姓名、身份证号（密文）、签署时确切的时间戳、访客手机设备指纹、访问公网IP地址以及当前生效的保密协议版本号（如V1.0.0）。
3. 版本动态控制：管理后台提供保密协议版本控制模块。当法务人员对协议条文进行修改并发布新版本时，系统将自动使所有历史签署状态对新来访失效，后续所有来访人员（包括老访客）均需重新阅读并勾选最新版协议。
4.2 本地基础数据库同步机制
同步本地现有数据库中核心字段。系统于每日凌晨02:00自动运行ETL存储过程进行单向数据清洗同步。
5. 信息安全与数据合规规划
5.1 敏感数据全程加密
采用行业标准的AES-256对称加密算法，对数据库中的身份证号、手机号以及访客保密协议签署记录进行落盘加密存储。全链路实施HTTPS TLS 1.3传输加密。
5.2 物业端严密数据脱敏
门岗物业保安端界面绝对禁止展示访客的完整身份证号，强制对身份证号倒数第5位至第8位（共4位，例如：3301021234****1234）进行掩码遮蔽（脱敏）。物业端无权查看任何保密协议的文本及签署详情。
